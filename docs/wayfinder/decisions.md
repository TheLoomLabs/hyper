# Wayfinder decisions

The long-form record of every closed ticket on the map —
[#1, *Map: `hyper` — a Go CLI for AI-authored, human-reviewable infrastructure
automation*](https://github.com/TheLoomLabs/hyper/issues/1) — in the order they
closed.

The map itself carries a one-line gist and a link per closed ticket, which is
what its format specifies and what keeps it loadable in one pass. This file is
that index at full resolution. A decision still lives in exactly one place —
its ticket — and neither the map nor this file restates one; both point at it.

Nothing here is normative. The specification is [`docs/spec/`](../spec/), the
rationale is [`docs/adr/`](../adr/), and the vocabulary is
[`CONTEXT.md`](../../CONTEXT.md). What this file records is the *route* — which
questions were asked, in what order, and what each one settled — for a reader
who needs to know why the spec reads as it does and cannot get that from the
spec, which states the *what* and never the *why*.

## [Swamp prior art: data model, execution semantics, and the decisions it made](https://github.com/TheLoomLabs/hyper/issues/2)

Swamp's real design, read from source at `5bfddaa` (27 internal `design/*.md` docs, 146 manual pages). **Falsified the charting session's supply-chain "correction"** (see Notes). Swamp has **no MCP server** and **no diff/drift**. Anti-patterns `hyper` must not copy: DAG edges come *only* from explicit `dependsOn` while accessors read from disk on every call (stale-read hazard for AI-written definitions); approval suspends and **exits 0**, so CI cannot tell a gated run from a success; extensions load via bare `import()` into the privileged host isolate with no declared permissions; a typed layer with a shell escape hatch; rollback that rewinds the record but not the effect (their own manual calls this "worse than partial writes"); pluggable-everything built then deleted. Worth stealing: the **sealed grant-condition CEL dialect** (a permanently weaker language for security decisions), **vault sentinels**, **unknown-key rejection**, **files-authoritative/index-derived** storage, **exit code 75** for retryable contention. Findings: [`docs/research/swamp-prior-art.md`](https://github.com/TheLoomLabs/hyper/blob/research/swamp-prior-art/docs/research/swamp-prior-art.md) on branch `research/swamp-prior-art` (~3,090 lines).


## [Domain model: what are hyper's primitives?](https://github.com/TheLoomLabs/hyper/issues/3)

`hyper` is **procedural, not desired-state**, so **diff means changelog** (this Run vs. the last), not *plan* — no Terraform-style pre-flight before a destructive change, which lands on the safety ticket. Spine: **Provider** (a **Manifest** — *data, not code* — plus an implementation) → **Definition** (the reviewed artefact; nothing runs except through one, which deletes Swamp's auto-definitions problem) → **Procedure** → **Step**. **Target** added (mandatory, with a reserved credential-free `local`; it is the unit of both blast radius and credentials, and absorbs what Swamp smuggled into `globalArguments` and patched with `vary`). `Data` split into **Observation** and **Asset** — an Asset exists *because `hyper` created it*, and the two are **never reconciled** (adoption is reconciliation by the side door). `Vault` **removed** as a primitive: secrets are a Target property plus a Manifest Capability, making secret access declared and checkable rather than a regex scan. Records keyed `(Target, Definition, name)`; **Run** is provenance, not identity, and carries **code identity** (Definition revision, Manifest digest, Extension digest, repo revision), closing Swamp's §11.3-7 gap. Operation **Kind** (`read`/`mutate`/`destroy`) is **declared, never inferred**; **`Opaque`** is a trait *orthogonal* to Kind, so `opaque`+`destroy` keeps its destructive flag. A Procedure may span Targets but must **declare the set**, checked before the first Step. Glossary: `CONTEXT.md` (18 terms). Stress-tested against all five real scenarios; four breaks found and closed.


## [Safety model for destructive operations](https://github.com/TheLoomLabs/hyper/issues/4)

**authority is statically decidable; magnitude is not** — the split the whole model hangs on. `hyper` does not prompt at the dangerous moment (there is none: CI is unattended); it makes most dangerous states unreachable from the artefacts and refuses the rest **before any effect**. *Static:* **two keys** — a Step runs only where the Definition's declared Kinds and the Target's accepted Kinds intersect, the Definition's claim **authored, not derived**, so widening is a visible edit; granularity follows severity (**Kinds** for read/mutate, **named Operations** for destroy); **transitive envelope containment**, so splitting a Procedure in two cannot launder blast radius — #3's "declares the full set of Targets" means *transitively*; `opaque`+`destroy` **off by default**, its opt-in travelling with the **credential grant**. **The environment is not an axis** — "CI may not destroy prod" is expressed as CI not holding prod credentials, never as an `is-CI` guess, so the guardrails are identical and laptop-testable. *Runtime:* **a selector may expand only over Assets** — foreign resources need a literal identifier, which kills orphan-overreach with no new primitive; a **Bound** checked at **Expansion** before the effect, mandatory on destroy (absent = unbounded = rejected), optional on mutate but its silence rendered; **halt, never compensate, never rewind the record** — Tombstones only on *confirmed* destruction (§13.5's silent divergence, forbidden by design). *Outcomes:* three — `completed`/`refused`/`failed`, never sharing an exit code (§9a.7's exit-0 bug unreachable); a **Refusal** is recorded in full with Provenance but writes no Records; **no `--force`, no `--skip-checks`, no bypass** ([ADR-0001](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0001-no-bypass-for-safety-refusals.md)) — the only way past is an artefact edit and a re-review. **Dry-run stops where it would have to lie**, and is a review aid, not a guarantee. Glossary +3: **Bound**, **Expansion**, **Refusal**.


## [Oversight artifacts: what does the human actually look at?](https://github.com/TheLoomLabs/hyper/issues/5)

**the artefact is the review surface; everything else is an index into it.** Rendering rule: **the gutter annotates what is in this file, a table aggregates what is assembled from elsewhere** — so a definition review shows the *artefact* with Kind/Target in a gutter (read it vertically and it *is* the step table, but it cannot lie by omission), while `AUTHORITY` stays a table because it is drawn from other files. The thing you review and the thing ADR-0001 forces you to edit are the same thing on screen. **Exactly one surface editorialises:** `FLAGS` may only cite a line the gutter already marked and may introduce no claim of its own, which makes a wrong summary structurally impossible rather than merely unlikely — the prose variant's "three things worth checking" was rejected on that ground. The change review is **three tables, one per actor**: **YOU DID THIS** (Assets) / **THE WORLD MOVED** (Observations) — a type split from #3, too important to be a column value — and, falling out of that, **THE CODE MOVED**, making provenance drift a first-class diff event, since an AI widening a destroy Bound between two Runs is the same kind of fact as a server disappearing and often the more important one. JSON is **NDJSON**, one row per table row behind a single renderer; accepted cost is that outcome arrives last, which puts new weight on #13's exit codes. A **Refusal** renders the caret excerpt *and* the `EDIT ONE OF` table and is deliberately the most verbose surface in the tool, because with no bypass it is the whole remediation path. Corrects a natural misreading of #4-10: no Records for the refused **Step**, not for the Run — completed Steps keep theirs, and the rendering says so. Constrains the authoring language to line-oriented text (see fog). Prototype: [`prototypes/oversight-surfaces.html`](https://github.com/TheLoomLabs/hyper/blob/prototype/oversight-surfaces/prototypes/oversight-surfaces.html) on `prototype/oversight-surfaces`, four variants.


## [Execution model: state, idempotency, partial failure, resumption](https://github.com/TheLoomLabs/hyper/issues/6)

**a Procedure is a sequence, a Run is never resumed, and re-running is the retry.** The ticket's headline question dissolved: with no graph there are no dependency edges to declare or infer, so §11.3-1's stale-read hazard is *unreachable* rather than mitigated, and "Step 5 reads what Step 6 writes" is a static error at review time ([ADR-0002](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0002-a-procedure-is-a-sequence-not-a-graph.md)). No `--from`, no reset graph, no run-state file — a resume file is exactly the shared state self-contained CI forbids, and it would resume into the state #4 refused to reason about ([ADR-0003](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0003-a-run-is-never-resumed.md)). What replaces the checkpoint is a **declaration**: **Repeatability** per Operation in the Manifest — `repeatable` / `skip-if-recorded` (the `(Target, Definition, name)` key *is* the identity) / **run-once by default**, which refuses on *evidence* (the Journal's Disposition: never-reached → run, ran or outcome-unknown → refuse), and a **Tombstone is not "recorded"** — the check reads the head version, so destroy-then-recreate rebuilds. State does not vanish, it changes character: the **Journal** is an append-only Run series carrying outcome, Provenance, and every Step's **Disposition** — the only home for a Refusal, and *history, never resumable state*. Records write **per Step**; a `kill -9` leaves an **open** entry that the next invocation closes `failed` with the in-flight Step *attempted, outcome unknown* — no reaper, no daemon. Concurrency is a function of **Kind** with the cap **Manifest-declared** (reads concurrent, mutate/destroy **serial**, Expansion deterministically ordered, no authored knob — §9a.3's level-wide `concurrency` trap unreachable); **no `allowFailure` anywhere** — the Provider declares result-vs-error as it declares Kind, so `hyper`'s rule is one line, *an error halts*, with read Expansions draining first. Conditions read **only earlier Steps' Records of this Run** — no live probes (§9a.6), no cross-Definition hidden inputs. Deadlines are per-Operation; signals **drain then die**; one Run spans nested Procedures (one outcome, one exit code, static cycle rejection); one store lock, **shared for read-only Runs**, contention `failed` with a distinct code (75). Two corrections to closed tickets: #4's Assets-only Expansion is **scoped by Kind** (reads may expand over Observations; effectful may not), and a **dry-run writes a marked Journal entry and is never a diff baseline**. The Manifest now declares **five** things per Operation — Kind, `opaque`, Repeatability, deadline, concurrency limit — all the same shape: *facts the Provider knows and the Definition author would be guessing at*. Glossary +3: **Repeatability**, **Journal**, **Disposition**.


## [Extension model and sandbox](https://github.com/TheLoomLabs/hyper/issues/7)

**an extension is data with no code in it** ([ADR-0004](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0004-extensions-are-data-not-code.md)). A Provider *is* a Manifest; `hyper` performs every effect it describes. WASM was the working answer for most of the session and was **eliminated on the merits, not deferred**: once credentials became host-mediated and Capabilities closed, a module's entire residual power was arbitrary computation over data `hyper` already held, and every concrete case for it argued for **growing `hyper` instead — reviewed once by everyone rather than separately by each consumer**. Go `plugin` (kills the static binary, zero isolation) and subprocess (ambient authority with no portable removal — §10.5 with extra steps) died on constraints already fixed. *One mechanism:* built-ins and Extensions are the same object, `go:embed`ed, total dogfooding; the trust difference lives in **distribution, not powers**, with one asymmetry — `Opaque` shell is **built-in-only**, so a third party can never ship a Provider that runs commands on your machine. *Capabilities:* the extension **never holds a secret**, so the grantable set is exactly the effects `hyper` can perform — a **closed enumeration `hyper` owns** (`http`, `dns`, `tls`, `tcp`, **`tls-no-verify`**; **no filesystem**, **no `exec`**, no bare wildcards), categorically unlike an npm/Deno permission list. **Declaration must equal derivation exactly, not by containment** — over-declaration is a *static error*, which does not soften #4's authored-Kinds rule (a Kind is a claim about the world, a Capability is mechanical). Derivation stays static because a Capability-relevant position may be filled only from a Manifest-declared **closed enumeration** or from the **Target declaration** — the split that makes self-hosted Providers expressible at all. **The Manifest declares, the Target grants**, the same two-key shape as Kind, which **forces the Target in two**: a reviewed, credential-free **Target declaration** (artefact) versus environment-resolved **credentials**, so #4's laptop-testable guardrails become true rather than aspirational and **holding a credential is not sufficient authority**. *Grammar:* Target constraints are **literal enumerated names** — a class only ever rejects, never expands, since a tag selector would widen a reviewed Definition without an edit; an Operation is **one call plus host-owned Patterns**, never a sequence, and **a Pattern may not change the Kind or the count**; **Record cardinality and identity are declared** per Operation, on which #3's key, #4's Bound and #6's `skip-if-recorded` all depend. Security decisions get **no evaluator at all** — set intersection rather than Swamp's sealed dialect, because a grammar that does not exist cannot grow. *Distribution:* **registry as source, repo as record** — `install` writes a tracked file verified by **digest only, never intent**; collisions are a loud load failure, never precedence; unknown-key rejection plus an explicit schema version. Handed #11 the leading twist candidate: *Swamp lets an AI write a program you must trust; `hyper` lets an AI write a description you can verify — mechanically, offline, before it touches anything.* Glossary now 28 terms (+3: **Target declaration**, **Pattern**, **Auth scheme**; **Capability** and **Extension** rewritten; **Provider**/**Manifest** corrected — no implementation exists behind them). Honest limit: **the ceiling is a wall, not a slope.**


## [Scheduling and cadence: who owns the clock?](https://github.com/TheLoomLabs/hyper/issues/8)

**`hyper` declares the Cadence and projects it; the clock is GitHub Actions'; and the record travels in the repository.** Cadence is a property of the Procedure (Steps already name their Targets, so a Procedure is *already fully bound* — "prod every 5 min, staging hourly" is two Procedures, sharing a nested one), written as **five-field POSIX cron, UTC only**, with a **mandatory gloss rendering runs-per-month** because *cadence is a blast-radius multiplier* — `0 0 1 * *` → `*/5 * * * *` on a destroy Procedure is ~8,600× the effect, reviewed nowhere if it lives in hand-written YAML. `hyper` **generates** the workflow in #7's `install` shape (tracked file, digest-verified, drift a loud failure), one file per Procedure ([ADR-0005](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0005-cadence-is-declared-and-projected-never-scheduled.md)). A daemon died twice (the constraint, and #6-13's *no reaper, no daemon, no heartbeat*); Swamp's `trigger.schedule` **does not transfer** — its cron registry runs only inside `swamp serve`. **A missed window is never made up** (a past Observation is unreadable; catch-up is the clock deciding to repeat an effect, which Repeatability decides on *evidence*; and Actions drops queued runs anyway) — so Cadence is a *lower bound on staleness*. **Then the ticket found its real problem:** a self-contained CI run **disarms #6** — with an empty store every run-once Step is `never reached` and `skip-if-recorded` never skips, so a nightly provision builds a VM *every night*, each an Asset that evaporates with the runner, and the **Bound cannot catch it** (magnitude 1 is correct). So **persistence is load-bearing for safety, not convenience**: an orphan **Store** branch in the same repo (the default branch died on ~105k machine commits/year; an object store would need authority to record authority), **one Store, two writers**, an effectful Run **syncs first or Refuses**, pushes **after every effectful Step** with the open Journal entry pushed at Run start, and the **Store is not a Target** — reaching it costs no Capability, which *validates* #7's closed set rather than growing it. #6-15's lock **projects** into an Actions `concurrency` group for effectful Procedures only, forcing one refinement: **only effectful Runs close open Journal entries**. Records **version only on change**; the **Trigger** on each Journal entry proves we looked, which is the only thing separating "nothing changed" from "nothing ran". Overdue **renders, never refuses**. Two corrections: **Provenance gains the `hyper` version** (after #7, it is the only code that runs) and **#6-13 narrows** to effectful Runs. Glossary now 31 terms (+3: **Cadence**, **Trigger**, **Store**; **Provenance** amended).


## [Secrets across laptop and GitHub Actions](https://github.com/TheLoomLabs/hyper/issues/9)

**`hyper` never stores a secret** ([ADR-0007](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0007-hyper-never-stores-a-secret.md)). No vault, no encrypted local store, no pluggable backend: a **Target declaration** names the environment variables its Auth scheme's slots are filled from, `hyper` resolves them once per Run and writes none of them anywhere — nothing is encrypted at rest because nothing is at rest. The ticket asked how one model spans both environments "without becoming two products"; the answer is stronger than the question hoped for — with credentials env-resolved on both sides, laptop and runner are **the same code path**, which is what finally makes #4's *the environment is not an axis* true rather than aspirational. The vault was declined on what it *obliges* (KDF choice, rotation, recovery, escrow, permission checks on every read), with Swamp §9c as the half-built version: PBKDF2-100k paid on every get, no AAD, **no rotation and no recovery anywhere in the tree**, an auto-generate key that is two concatenated UUIDs, `.key` permissions validated on write and never on read. Password managers are handled by **wrapping the invocation** (`op run --`, `direnv`, `aws-vault exec --`) — a resolver *command* in the declaration was rejected as ambient-authority code named by a reviewed artefact that also cannot run on a runner. *Reading, not acquiring:* OIDC federation is **not implemented**, and the fork mattered most for what it **permanently ruled out** — the ecosystem answer of a third-party action inside a `hyper`-generated workflow puts the supply-chain problem back in the very artefact whose reviewability is the headline claim; if federation is ever needed it arrives as Auth schemes `hyper` owns. *Authoring:* **explicit env var names**, not a derived convention, because the declaration *is* the authority review surface and `env: STAGING_TOKEN` → `env: PROD_TOKEN` must be a visible one-line edit; **a literal in a credential position is a load-time error**, which answers "how does an AI reference a secret it must never see" positionally rather than with a scanner. The CI secret surface is **generated** from the Procedure's transitive Target set, Actions secret and env var sharing **one name**, so adding a Target makes a new secret appear *in a diff*. *Outputs:* the Store is a pushed branch, so the rule holds for what an Operation **produces** — a Manifest declares secret output fields and the Record carries a **presence-only redaction marker** (a digest would give #5's *THE WORLD MOVED* a real rotation signal and also publish an offline-crackable oracle; **#12 may reopen this**). **Then the ticket found the consequence nothing had handled:** #8 made unattended effectful Runs real and a secret-producing Step has *nowhere to put its output* — but *refuse when unattended* is illegal under #4, so it became a property of the invocation instead: a **Secret sink** is supplied or the Step **Refuses**, environment-blind and laptop-reproducible by omitting the flag. A path (not stdout, which #5 made one NDJSON renderer; not an fd, unusable from MCP), `0600`, and **refused if it resolves inside the repo working tree**. Price: an Asset whose only handle *is* its secret is not re-readable — you rotate, not recover. *Gates:* credential **presence** checked before Step 1 for the whole declared Target set → **Refusal**; validity never probed, so a bad credential is `failed` — lazy checking was worst under #6 (a Run dying at Step 40 leaves run-once Steps permanently unreachable). Credential positions are **suppressed positionally, never scrubbed**, which holds *only* because a Provider cannot invent an Auth scheme. **No audit log** — Swamp's untamper-evident `vault-reads-*.jsonl` is replaced by a query over the Journal, which already carries every Step's Target. Glossary now 32 terms (+2: **Target credentials**, **Secret sink**; **Auth scheme** amended).


## [MCP surface design](https://github.com/TheLoomLabs/hyper/issues/10)

**twelve tools, and the surface's job is to make the artefact easier to write correctly, never to write it**: `hyper` writes what it *derives*, the agent writes what is *reviewed*, so no tool authors a Definition, Procedure, or Target declaration and what `hyper` owes instead is discovery plus a `check` positioned by file and line — the next act is an edit, the same act ADR-0001 forces on a human. **Tools only** (resources are client-controlled and in most clients user-attached, so Manifest discovery behind one is unreachable exactly when needed; prompts are the per-editor glue this project departs from). The surface **executes, destructively included** — restricting it would encode *who is calling* as an authority axis, and #8 already made unattended effectful Runs normal, so an agent call with a human present is strictly safer than a case already accepted. Returns are **#5's row set unchanged** plus an asymmetric text block: ordinary returns lead with the outcome in one line (repairing #5's accepted cost — NDJSON puts the outcome last and MCP has no exit code), while `review` and a Refusal return the full rendering. **`isError` is true for both refused and failed** — one bit cannot carry three states, so `outcome` is the discriminator as #4 required — and **every Refusal states that a verbatim retry will refuse identically**, the one new failure mode this surface introduces, since `isError` conventionally invites a retry and with no bypass a retrying agent loops forever. **A Probe is not a Run** ([ADR-0009](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0009-a-probe-is-not-a-run.md)): #3's friction is smoothed by a bounded exception — `read` Kind, `local` Target, **no Record and no Journal entry** — which is a door rather than a loophole because with no Record there is no `(Target, Definition, name)` key to need, and against `local` the two-key check is *vacuous rather than skipped*; the argument is not convenience but that **#5's review model dies by volume**. **A Procedure is fully bound** ([ADR-0008](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0008-a-procedure-is-fully-bound.md)) — writing `run`'s signature forced the authoring language's hand: an input is **authority arriving after review**, the shape of the `--force` ADR-0001 removed, and #8's no-unbound-inputs rule, #5's gutter, and the new Probe all already pointed there. Discovery is **three levels** with **Kind at level 2** (answering #4's two-key check before any schema is fetched) and **Repeatability plus Bound-required at level 3** (authoring facts, not call-time facts), returning **Manifest source text** — #7 made it the same format a Definition is written in — plus a projection of what the source does not carry verbatim. **`install` is excluded**: it is the single point where third-party data enters the repo, and an agent that can install can author against it and run it in the same turn — *the line is acquisition, not derivation*, so #8's Cadence projection stays reachable. **Synchronous with progress at Step boundaries** (an async handle is a daemon with extra steps; a client timeout is already specified by #6 as an open Journal entry closed `failed` with the Step *attempted, outcome unknown*), at the named cost that **a twenty-minute provision is not practically runnable from MCP** — that is #8, not a gap. **Truncation has a marker and no cursor**, naming the axis dropped, because pagination is the same context blowout arriving politely. Prototype: [`prototypes/mcp-surface/`](https://github.com/TheLoomLabs/hyper/tree/prototype/mcp-surface/prototypes/mcp-surface) on `prototype/mcp-surface` — written schema plus a zero-dependency stub server. Glossary now 33 terms (+1: **Probe**).


## [Find the twist: what makes hyper better?](https://github.com/TheLoomLabs/hyper/issues/11)

**the twist was already chosen; this ticket named it.** *Nothing reaches the world unreviewed; nothing changes unseen* — two co-headlines, one loop, each covering the other's blind spot. Judged against the **wide field** (bare MCP servers, Ansible, Terraform), not Swamp alone, since beating one Deno program by one author proves little; and against a **three-part bar** — compresses to one unshruggable sentence, demonstrable on one screen with no infrastructure, structurally uncopyable. *Verdicts:* the **static binary killed** (`deno compile` ships one too — table stakes); **MCP split**, the transport demoted to a consequence but #10's *policy* kept as headline 1 at the surface — "we have an MCP server" is a weekend, "our MCP server refuses to write the artefact for you" is a position almost nobody would take; **cadence** a consequence (authority-in-the-reviewed-artefact, applied to time); the **sandbox superseded** by #7 having removed the code; **drift-and-change promoted to co-headline** and renamed. *The two skeptic questions, both new to the map:* **"why isn't this just a pile of MCP servers?"** — an MCP server makes the *call* typed, `hyper` makes the *decision to call* reviewable; a tool call is ephemeral and leaves nothing a human reads afterwards, lacking a durable reviewed artefact, a Record, a Bound, and a Refusal it cannot argue past. **"Terraform shipped a diff in 2014"** — **opposite direction in time**: `plan` is prospective and needs the reconciliation engine #3 declined, `hyper`'s is retrospective, and no `plan` says *which revision of the code did this* ([ADR-0010](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0010-hyper-has-no-plan.md)). *Three costs, all going into the spec in the tool's own voice:* the **ceiling is a wall** and is accepted *deliberately, not reluctantly* — a description language expressive enough for arbitrary computation is a program you must trust, so the ceiling is the claim stated from the other side (ADR-0004 amended); the **Comparison prevents nothing**, being accountability rather than guardrail, with every guardrail static and before the Run; and **only half the demo is free** — `THE CODE MOVED` renders offline from two Definition revisions while the world-facing tables need two real Runs, so the one-screen demo is `check` → `review` → `THE CODE MOVED`. *Vocabulary:* **"drift" struck project-wide** — it promises the reconciliation #3 declined, and `CONTEXT.md` never had the term, which was the evidence; the word is **change**. Glossary now **34 terms** (+1: **Comparison**, _Avoid_: Diff, Drift, Plan, Changelog, Delta), with "change review" and loose "diff" swept out of `CONTEXT.md` and ADRs 0006/0007/0009.


## [Data layer: storage, query, Comparison, and redaction](https://github.com/TheLoomLabs/hyper/issues/12)

**the Store is append-only, the Head is derived, and nothing in it is ever rewritten** ([ADR-0011](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0011-the-store-is-append-only.md)). The ticket's five bullets were one question wearing five hats: #8 put the record on a git branch with two writers, which makes *every file that gets rewritten* a correctness problem rather than a matter of taste — and Swamp's `latest` marker, its mkdir-as-mutex allocator and its per-Record counter all fail that test together, each assuming one writer on one filesystem. *Storage:* files authoritative, index **derivable but not built** — a version is a file named by the Run that wrote it, at `records/<target>/<definition>/<name>/<run-id>.json`; the **Head** is derived by `written_at` order because *the working tree must be self-describing* (which is also why commit order, the more correct option, lost). One file per version, canonical sorted-key JSON, Provenance **duplicated** rather than referenced, **no binary and no streaming**; a **Tombstone is an ordinary version** and does not end a series, which is what makes #6's destroy-then-recreate work. The Journal entry is a **directory** — `run.json`, `steps/NNNN.json`, and an `outcome.json` that appears at the end — so #6's open entry is simply the absence of the terminal file, and even **reaping stays append-only**. Because `name` is a Manifest-declared field of an *upstream response*, it is hostile input: paths are percent-encoded with case preserved and a case-insensitive key collision is a **Refusal `hyper` enforces by reading the Store**, never by attempting a write, so a case-insensitive laptop and a case-sensitive runner cannot disagree — #4's *the environment is not an axis*, again. An absent Store branch is **never created implicitly**, read-only Runs included. *Query:* **no query language** ([ADR-0013](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0013-hyper-has-no-query-language.md)) — Swamp's CEL allowlist's best property (an error listing the valid vocabulary) is cheaper from typed parameters, which state it *before* the call; #4's *which Assets have an unconfirmed destroy* becomes a **parameter on `records(...)`**, which requires a Disposition to record **the identities it acted on**, so #4's decision 8 stands with no new state on the Asset. *Comparison:* baseline is the **previous Run of the same Procedure**, defined between two Journal entries. **Then the ticket found the hole its own decisions had opened** — Records version only on change, so an unchanged Record is byte-identical to a **vanished** one, and `THE WORLD MOVED` could not render a disappearance or even say *we looked and nothing moved*. Fixed by generalising the Disposition: **every Step records the identity set it saw, reads included, as a digest, with the full set written only when the digest moves** — one line for an unchanged 500-VM listing, no reconciliation, and cadence volume lands in the Journal where it belongs. `moved` **dropped** from #10's change classes (a rename is a vanish plus an appear; asserting otherwise is reconciliation), and the three tables **never join an Observation series to an Asset series**. `THE CODE MOVED` reports a **closed enumeration including the selector** — nearly omitted, and rendering a Bound 10 → 500 while silent about a selector going from one VM to every VM would be truthful and still misleading — terminated by a mandatory catch-all count. A Refusal gets **no row**. *Safety correction to #6:* **a dry-run entry is evidence that a rehearsal happened and evidence of nothing else** — the other reading has a dry-run permanently poisoning every run-once Step in a Procedure, with no bypass to escape it. *Redaction:* **not reopened** — a digest published once into a non-editable history is published forever; the rotation signal comes from the API's own key id or fingerprint, projected as a non-secret neighbour, and the marker stays **in-place, redacted, unknown**. *Retention:* read-time, never frozen, and living in a **reviewed artefact** — a `--keep-versions` flag would be the `--force` ADR-0001 removed. **Compaction** touches interior Observation versions only, and the honest limit is stated rather than implied: it **never reclaims clone size**. Also **[ADR-0012](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0012-deleting-a-definition-abandons-its-assets.md): deleting a Definition abandons its Assets** — cascading would make deleting a text file a destructive Operation with no Step, Bound, Kind or Target check; blocking would let the Store veto an edit to the repository. Vocabulary: #10's `diff(...)` is renamed **`changes(...)`**, and a glossary error found in passing — `CONTEXT.md` still carried #4's Assets-only Expansion, which #6 overturned. Glossary now **37 terms** (+3: **Head**, **Orphaned Asset**, **Compaction**; **Expansion** corrected, **Tombstone** and **Comparison** tightened).

## [Observability: does the Journal suffice, or does hyper need tracing?](https://github.com/TheLoomLabs/hyper/issues/14)

**the Journal suffices, and asking why found three things it was not recording — none of them performance.** **[ADR-0016](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0016-hyper-has-no-telemetry.md): `hyper` has no telemetry** — a Run is one process running one sequence, so there is a single root, nothing concurrent to reconstruct, and after ADR-0004 **no second process to propagate a trace context into**, which is exactly what Swamp's `TRACEPARENT` does; their own README says its OTel is *"most useful for long-running `swamp serve` daemons"*, the architecture this map put out of scope. Recorded as an ADR because *nothing was added* is the hardest decision to reconstruct later. *What was missing:* **(1) the Journal recorded no time at all** — #12's Comparison header rendered a `started` the Journal did not carry — fixed with **timestamps, never stored durations** (the files are already written at those instants; a stored duration is a second representation that can disagree), which buys the crash case for free: an **open** entry's last Step file says *when the Run went quiet*. Plus the rule keeping it honest — **a duration is only ever computed inside one Journal entry**, since the laptop and the runner share no clock; ADR-0011 names the exposure, this states it positively, and #12's Head derivation is **not** reopened. **(2) a Step recorded nothing about what `hyper` itself did**, which is a safety hole rather than a metric: a **Pattern** is host-owned code, so **retry is the one place `hyper` can touch the world more times than the artefact says**, and `attempted, outcome unknown` after five attempts is a different fact from after one. Recording is necessary and **not sufficient** (#11: the Comparison prevents nothing), so both — every **Disposition** carries a closed, `hyper`-owned pattern record (attempts, pages, polls), never Provider-supplied, on the same grounds as `error_code` and Auth schemes; and **[ADR-0018](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0018-retry-only-follows-a-failure-that-provably-preceded-the-request.md): retry only follows a provably pre-send failure** — connection refused, DNS, TLS handshake; never a timeout, a mid-flight reset, or a 5xx. A **correction to #7**, whose "may not change the count" meant *Records*; a retry on a non-idempotent mutate changes the count in the *world*. `read`-only retry buys no safety over the pre-send class while sending every routine 503 to the wall; **gating on Repeatability** was the elegant-looking wrong answer — `repeatable` presumes the first call **completed**, retry presumes it **may** have. It needed an ADR because the class is `hyper`'s own code, so **widening it later moves nothing a human reviews**. **(3) an open Journal entry was unqueryable** — `runs(outcome:)` takes the closed triple — so **`open` is a state, not an outcome**: `runs(open: true)`, never a fourth outcome value (which would leak into #13's exit-code table), rendered without guessing as *the Run may be in flight or the process may be gone*, since asserting either is a heartbeat. **No watch, no `--follow`.** *The wire:* **[ADR-0017](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0017-the-wire-is-visible-only-where-no-credential-was-used.md) — visible only where no credential was used.** A **Probe** may show the raw response beside the projection; a credentialled Target never does, because a dump reinstates the catch-all bucket ADR-0011 closed, on the widest surface there is. Dumping only undeclared fields inverts the guarantee — a closed allowlist becomes a denylist over hostile input. What fills the gap is precision: a projection failure carries a closed `error_code` and **the path that failed to project**, positional as ADR-0007 is positional. *Linkage:* the **Trigger** now carries the executor's own run identity (Actions `run_id`/`run_attempt`/job URL), since #13's stderr narration lives in a log the Journal could not point at. *Rendering:* durations on `runs` and the Comparison header; pattern facts **only when not the trivial single call** (#12's digest-by-default precedent) and **never in the three tables** — how hard `hyper` worked is not a code fact. Glossary unchanged at **37 terms**, three amended (**Disposition**, **Journal**, **Pattern**): every fact here was something an existing term already meant and did not say.


## [Distribution, install, and version pinning](https://github.com/TheLoomLabs/hyper/issues/15)

**the version of `hyper` is authority, so it lives in a reviewed artefact — and asking where to put it found the artefact #12 created and never named.** The ticket reads as packaging and is not: ADR-0004 removed the code from Providers, so the binary is the only code that runs and a version bump moves Bound checking, Expansion ordering, Repeatability evidence and redaction at once — the largest change in the system, and the last one reaching the world without appearing in a diff. **[ADR-0020](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0020-the-hyper-version-is-pinned-by-the-repository.md): the version is pinned by the repository and enforced in both environments.** ADR-0005 already ended with *the generated workflow pins the version*; stopping there pins the runner, leaves the laptop free, and both write one Store — #4's **environment-as-authority-axis arriving through packaging rather than policy** — and it has nowhere to live in a repository declaring no Cadence. So the gate is universal: **every command Refuses on mismatch**, `version` and `completions` the only exemptions, and **`check` is gated deliberately** because a `check` passing under a newer binary that the pinned one would Refuse is a false green on the one surface #13 built to be trusted. **The pin is derived, not authored, and `hyper project` is the only door** — #10's *`hyper` writes what it derives* puts a fact about the binary on `hyper`'s side; the ritual is *install → project → read the diff*, ADR-0001's shape exactly, and it settles **#13's open `project`/`cadence` naming question** since `project` now projects everything derived. An absent pin **Refuses (77) naming `project`**, so deleting the file is a dead end rather than a bypass. *The home:* the **Repository declaration**, parallel to Target declaration, naming what #12 left as *"a reviewed repo artefact"* and absent from the glossary while load-bearing for Compaction. It **amends [ADR-0014](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0014-hyper-has-no-configuration-files.md)**, which anticipated it in terms (*a setting that matters belongs in a reviewed artefact*), and the **admission rule is part of the decision** rather than later discipline — only facts governing the repository as a whole and belonging to no Procedure, Definition or Target declaration; two qualify, the pin and retention. `review` accepts it and **glosses** it in ADR-0005's spirit: a pin you cannot check against the binary in front of you is a number, not a review. *Fetch:* a release artefact fetched by a **shell step written into the generated workflow** — version, URL and digest literal, nothing resolved at run time; a setup action rejected **even first-party**, since #9's objection is to code running in the job before `hyper` does. **Digest on #7's rule with no exception earned** — registry as source, repo as record, never intent — but **at the fetch, not at the gate**, and this runs against the map's derived-over-declared instinct on purpose: **a self-hash is a check the checked party performs on itself**, so a binary lying about its version lies about its hash, and only the platform the workflow's `runs-on` names is ever fetched. Getting that digest is **trust-on-first-use, named rather than glossed** — a binary cannot know another platform's digest of its own release, so `project` fetches the published checksum once and freezes it, converting a **mutable pointer** (a release asset can be replaced under its tag — Swamp's *pinning is advisory*) into an immutable reviewed fact. Projection is **repo-wide and all-or-nothing**, since a per-Procedure selector would let two Procedures pin different versions against one Store. An unreleased binary **works locally and cannot project**, the checksum simply failing to resolve. *Skew, the ticket's real question,* is answered by construction — laptop and runner provably run the same code — with a hand-edited pin caught twice (projection drift, and the fetched binary Refusing). What remains is history: ADR-0011 makes **in-place format migration impossible**, so the Store accumulates every version's files forever — **a schema version per file, never per branch** (a branch marker would have to be rewritten), read at or below the binary's own, **Refusing never guessing on a newer file**, and it is an **independent monotonic integer** rather than the release string, which Provenance already carries. **The release version promises nothing**: no *surely a patch release is fine*, the schema integer the only mechanical compatibility fact. **[ADR-0019](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0019-hyper-never-updates-itself.md): no self-update and no update check** — the second half is the one worth recording, being egress on nobody's behalf, declined on ADR-0016's telemetry grounds. **Correction to #12:** `THE CODE MOVED` has no row shape for a repo-wide fact, yet #12 promised retention would render there; leaving it to the catch-all is #12's own selector argument turned on its largest case, so the **closed enumeration stays per-Definition and the Comparison header gains the Repository declaration's facts** — *which binary drew this comparison* is a property of the window. Honest limit: **you cannot read an old commit's Store without that commit's binary.** Glossary now **38 terms** (+1: **Repository declaration**).


## [Notification, and a tool that only ever renders](https://github.com/TheLoomLabs/hyper/issues/16)

**`hyper` never speaks first ([ADR-0021](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0021-hyper-never-speaks-first.md)) — and the answer got smaller than the question because two of the ticket's four "invisible" cases were already visible.** A Refusal is a *terminal* outcome (#4) exiting **77** (#13) and a halted destroy is `failed` exiting **1**; the ticket's headline example, *a Run that completed while every Step Refused*, describes a state the outcome triple makes unreachable. *The position is not a refusal:* **the notification you want is a Step** — a Definition against a Slack Target, `mutate`, `http`, credentials from the environment — reviewed, Bounded, recorded and Compared like everything else, so egress was declined without declining the use case. The argument is the thesis turned on the tool itself: `hyper`'s own outbound message is a destination no reviewed artefact named, a credential ADR-0007 says it does not hold, a second redaction path, and a Capability that cannot join #7's closed set without being a wildcard — **a notification *is* reaching the world**, and exempting our own is losing the argument. ADR-0016's explicit hand-off of egress is discharged. **The ambient signal already exists and is not ours**: a nonzero exit fails the job and GitHub notifies *the user who last modified the cron syntax*, which after ADR-0020 is whoever committed `hyper project` — **derived rather than configured**, and a channel of our own would be the only part of the system whose delivery `hyper` could not record. *The one place it speaks is a rendering:* the projection carries **two invocations** — the Run, then `changes` under `if: always()`, since a one-invocation workflow renders the Step narration and leaves the Comparison, half the thesis, unrendered — **`tee`d to `$GITHUB_STEP_SUMMARY`**, with the load-bearing detail being **who knows**: the workflow redirects and the binary is told nothing, because detecting the variable is the is-CI axis #4 deleted wearing a helpful costume. **Fenced text, not a Markdown mode** (a third renderer against #5's *one renderer* and a fourth global against ADR-0014's three, to buy prettier tables; colour is never load-bearing, so the summary carries identical information) — **so the job summary is not a new surface, it is the existing renderings relocated**. **`tee` not `>>`**, because GitHub drops an oversized summary *without failing the step*, which would make it absent exactly when the Run was largest. No branching on Refusal: #10 already returns the full rendering on stdout, so the failure email lands on the rendered remediation path ADR-0001 requires rather than a log. *Silence is a fact you can read, not a state the tool asserts:* wherever a Cadence is glossed the last Journal entry renders beside it (`≈4.3 runs/month · last ran 41 days ago`) and **`hyper` never says *overdue*** — a threshold is the tool introducing a claim of its own on the one surface #5 built to forbid it. A **watcher Procedure** killed explicitly (a daemon in a cron costume, switched off by the outage it monitors), no new command. *Three limits, decided not deferred:* **you cannot author "tell me when this fails"** — an error halts so the notify Step is never reached, and no Step can see an outcome that does not exist until the Run ends, so **an authored notification can announce that something happened and never that something failed to happen**; **a green check means the Run finished, not that anything happened** (every Step skipped, exit 0 — no fourth outcome, on #14's precedent), which is where the *Asset adoption* price is now visibly paid; and **two executor failures `hyper` can neither see nor prevent** — a schedule auto-disabled after 60 days shows *no run, no error and no banner*, and an oversized summary vanishes silently. Both rejected escapes die on closed decisions: a **failure-conditional Step** is ADR-0002's edge rebuilt into the post-halt state #4 refused to reason about, and a **Store-reading Provider** makes the Store a Target by the side door (#12) *and* shares the watcher's fatal symmetry. A **local ping** survives the egress argument and dies as an is-a-TTY axis. **ADR-0005 amended twice** (two invocations and the summary; *overdue renders* sharpened to adjacent facts, never a judgement); **`review` is not in #13's Store-requiring set**, degrading to `last ran: unknown (no Store)` rather than Refusing, which keeps the offline authoring loop intact. Glossary unchanged at **38 terms**, **Cadence** amended — there is no *overdue* to name, and both existing terms turned out to have meant it already.


## [The authoring language: one format for five artefacts](https://github.com/TheLoomLabs/hyper/issues/17)

**strict-subset YAML, and no expression language anywhere** — and drafting all five artefacts broke the format in five places, two of which were a closed ticket's requirement finally getting a syntax. *The format:* YAML 1.2 core with anchors, aliases, merge keys, tags, multi-document files, implicit typing and unknown keys **rejected at load** ([ADR-0023](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0023-the-authoring-format-is-a-strict-yaml-subset.md)) — chosen because the primary author is an AI, which makes **corpus a first-class design input**, and because every footgun is removable by *rejecting*, this map's move everywhere else: **a restriction is reviewable; an invention is unlearnable**. **HCL was the serious contender** and lost specifically: its corpus is Terraform's, so a model writes `${var.x}` and `try()` by reflex — banning what the corpus teaches is worse than having no corpus — and it imports the desired-state model ADR-0010 rejects. Banning anchors is #5's rule, not tidiness: *the line you read must be the value used*, an objection that independently killed `$ref` and recursive descent — **three appearances of one argument**. Typing is **schema-directed**, killing the Norway problem by construction rather than by blocklist, and it is *total* only because inputs force `additionalProperties: false`. **Outputs get no schema at all, only the projection** — a second representation of a declared fact can disagree with it (#14's stored-durations argument). *No expression language* ([ADR-0022](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0022-the-authoring-format-has-no-expression-language.md)): #7 took *a grammar that does not exist cannot grow* as far as authority checks; this extends it to the whole format, **and the deciding argument is review, not simplicity** — `age > 14d` → `age > 1d` is one character on one line, where a structured predicate list gives every predicate its own line, which is what #5's gutter annotates and what #12 demanded of the selector. **The format's shape and the review surface's shape are the same decision.** The path grammar shrank twice to `$`, `.member`, `["member"]` and nothing else — `[n]` dies on #7's own identity-is-array-position hazard, and **`[*]` belongs to no grammar at all** once iteration is declared once in `record.over`, which makes #7's *a Pattern may not change the count* **structurally unsayable** rather than checked. **No regex** (`.*` is two characters that mean everything) and **no `any_of` — on safety, not simplicity**: a **Bound** is per-Step, so an `OR` puts two disjoint populations under one count while two Steps give each disjunct its own Bound, gutter row and Comparison line. **References are mappings, not strings**, legal only where the schema expects a scalar. *Positions, not scanning:* one template-hole syntax with **legality decided by position** (enumeration or `from-target` in Capability-relevant positions, Operation input elsewhere, credential slot inside `auth:` **and nowhere else** — which makes *`hyper` knows which positions carry the secret* mechanically true); **no wildcard of any kind**, which **sharpens #7** — its `*.amazonaws.com` illustration would degrade declared-equals-derived to the containment #7 forbade in the same paragraph, and `s3.{region}.amazonaws.com` over 35 enumerated regions is finite and exact. A credential slot's value is **a mapping whose sole key is `env:`**, so *literal or reference* is a **type** question rather than a parsing one, and **`env:` appears nowhere else in any artefact**. *Layout:* fixed and **not configurable**, with a mandatory `kind:` that must **agree with the directory** — declared *and* derived — and `target-declaration` rather than `target`, because #12 caught a live glossary error by being strict about exactly this. **Only a Manifest carries a format version, correcting #7:** ADR-0020 pins the binary repo-wide, so every artefact in the working tree is read by the binary the repository pins and there is no skew to version against — the line is **inside versus outside the pin's reach**, and four of five review surfaces lose a field. `hyper project` **writes exactly the pin and its digest** in `hyper.yaml`, which is not a #13 violation because #13's whole-file rule protects files that are *entirely* derived. *Then drafting broke it five times:* **(a)** `local` and the no-wildcard rule collide and **an uptime Provider was unwritable** — fixed by **`local` being about credentials, not reach** ([ADR-0024](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0024-local-grants-enumerated-hosts-like-any-other-target.md)), since an unconstrained-host `read` is an **exfiltration channel** the moment a host arrives from a Record rather than the artefact; **dynamic host discovery is now impossible**, the population may come from data but the *reach* only from an artefact. **(b)** `over:` needed a third form — **`values:`**, a literal enumerated list — which is not a new permission but the syntax `CONTEXT.md`'s **Expansion** entry had always required and never supplied; it yields a new static check, **`values:` ⊆ the Target's granted hosts, offline and credential-free**. **(c)** **the Definition carries authority only and holds no argument values**, decided by #5's rendering rule rather than taste — values elsewhere force a second `AUTHORITY`-shaped table, the "wrong summary" surface #5 made structurally impossible. **(d)** **`when:` had no Disposition** — a **sixth** one, `skipped by condition`, because collapsing it into `skipped as already recorded` is unsafe in *both* directions (a condition-skip would poison a run-once Step with evidence it never earned). **(e)** `from-target` meant two things and now denotes **a Target's granted host set**, Proxmox being that set with one member. Also: **Expansion is scoped to the Step's own Definition and Target** (the Target half being blast-radius laundering through the Store); **a reference to a `series` Step is a load error**, since any pairing rule is #12's forbidden join arriving through the argument list; a **nested Procedure invocation is an entry in the same `steps:` list**, a second list being ADR-0002's graph by the back door. Glossary still **38 terms** — no new ones, mirroring #13 and #14 — with **four amended** (**Definition** no longer *configured*, **Local**, **Expansion**, **Disposition**). Honest limits: **three more named victims for the wall** (disjunction, regex, arithmetic), and *does this Manifest correctly describe its API* is exactly as unowned as #7 left it.

## [The Auth schemes: which ones `hyper` implements](https://github.com/TheLoomLabs/hyper/issues/43)

**the set is two, both of them a request header, and it closes at two because of one sentence that also refuses the four things it leaves out.** [ADR-0031](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0031-an-auth-scheme-is-a-header-and-a-placement-never-a-protocol.md): **an Auth scheme is a header and a placement, never a protocol** — it decorates a request `hyper` was already making and does not fetch, exchange, refresh, or sign. *The membership:* **`header:`** (`name:` plus an optional `prefix:` concatenated verbatim, one slot `token`) and **`basic:`** (no parameters, slots `username`/`password`). A bearer token, an API key in any header and Proxmox's compound token are **one placement rather than three schemes**, so **`bearer` is dropped** — beside a parameterised `header:` it is a second spelling of a byte-identical request, the second-representation-of-one-fact refused six times already, and it would render as a change in `THE CODE MOVED` while nothing moved. **`auth:` is optional**, absence meaning no credential is sent and rendered as `none`, on `repeatability:`'s undeclared-default shape; `none` is not a third member, a scheme being *a way of authenticating a request* and not authenticating one not being a way of doing it. *Naming a header is not choosing a position* — the position class stays the scheme's, so suppression stays mechanical — but a scheme may not name a header `hyper` computes, five of them, refused as **`auth-header-reserved`** (thirty-five → **thirty-six**), a new code on `capability-reserved`'s shape because what is refused is drawing on a name the tool holds rather than an internal contradiction. **`Host` is what makes it a guardrail**: derived from the value the grant was checked against, so a scheme setting it would dial a granted host while claiming another. The verbatim `prefix:` puts a load-bearing trailing space where no reviewer can see it, fixed by a **rendering rather than a check** — `provider <name>` renders the composed header with `<secret>` in the credential's position, so an omitted space reads as `Authorization: Bearer<secret>`. *One position:* a query parameter, URL userinfo and a body field are refused for the guarantee it buys rather than the principle it offends — **no secret ever appears in a URL**, mechanically, rather than by convention, since promising suppression in a URL is promising what every proxy and access log on the path makes false. *Four things fell out that the ticket did not ask for:* **two of §12's three hole positions collapse** — a Capability-relevant position is now exactly one, `host:` (narrowing ADR-0029), and a scheme's parameters do **not** fall back to resolving to an Operation input, which would let a Step's arguments choose the header a credential lands in, so they become **the one position where a hole is refused outright**; **presence and the projected `env:` block narrow from the Target declaration to the binding**, correcting an over-reach [#41](https://github.com/TheLoomLabs/hyper/issues/41) created, under which a Target serving two Providers made a Run Refuse for secrets it would never send and, worse, **put secrets in a CI job that no Step could reach**; **`local`'s credential-free-ness becomes a consequence of slot coverage** rather than a reservation; and **`THE CODE MOVED` gains a ninth class, the credential source**, without which [#9](https://github.com/TheLoomLabs/hyper/issues/9)'s whole explicit-env-var argument — `env: STAGING_TOKEN` → `env: PROD_TOKEN` is a visible one-line edit — reaches the Comparison only as one line in the catch-all count, names only since a rotation behind an unchanged name is a world fact ADR-0007 declined to see. *Costs:* **four victims for the wall**, eight → **twelve** — request signing and with it **every hyperscaler**, an OAuth2 token `hyper` fetches, a client certificate, and an API whose secret lives in the URL (Slack's webhooks) — plus a rendering loss stated beside the wall rather than on it: a vendor's bundled identifier is suppressed with the secret it is packed against, so no surface reports *which* token a Run used. And one consequence that reads as a limit and is the model asserting itself: **a Target holds one credential per scheme, so two credentials are two Targets**. Glossary unchanged at **38 terms**, **Auth scheme** amended — this ticket named a set, not a concept.

## [What the temporal predicate operators measure against](https://github.com/TheLoomLabs/hyper/issues/46)

## [Expansion order over encoded or raw identities](https://github.com/TheLoomLabs/hyper/issues/52)

## [The gloss's phrase grammar and its rate](https://github.com/TheLoomLabs/hyper/issues/61)

**a step is not an interval, and a rate has no year in it** ([ADR-0066](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0066-a-step-is-not-an-interval-and-a-rate-has-no-year-in-it.md)) — both halves of the ticket had one defect underneath them: the obvious implementation of a gloss reads something other than the five fields. *The phrase* is a **total function of the five fields and structure-preserving** — each field renders **in the form it was written in**, which bounds the phrase's length by the **expression's own length** (nothing can explode) and lets a reader map every clause back to the field that produced it, making ADR-0063's *a reader who disagrees with a gloss can check it* mechanically true rather than plausible. A phrasebook with a fallback was rejected for stopping being total exactly where the expression is hardest to read, which is the case the gloss was made mandatory for; three clauses in fixed order, an unrestricted field silent, `UTC` attached once, leaving `* * * * *` as the one expression naming no timezone. *The find:* **`*/7` is not *every 7 minutes*** — it selects 0, 7, …, 56 and then waits **four** — so the unaided reading is a **false sentence** on the surface ADR-0005 made mandatory *because cadence is a blast-radius multiplier*, and it would be the first thing a gloss ever introduced; it is wrong only where the step does not divide, which is what makes it dangerous, the phrase being the artefact a reader was given so they would not have to read the cron. Interval language is admitted **only where `n` divides the span, on minute and hour alone** — never day of month (span 28–31, `*/10` naming a 31st most months lack), and never month or day of week, there by the rule *paying off* rather than by exception: *every 3 months* does not say **which** three. *Three smaller rules:* **order and repetition normalise and the form never does** (`5,1,3` ascends; `0-59` stays a range and glosses awkwardly, because somebody wrote a range where `*` was meant and that is a fact about the artefact on the surface built to show them); the time clause **merges minute and hour only where the merge does not lengthen it**, since merging further takes the cross product and `*/5 9-17 * * *` is 108 clock times — the one way a structure-preserving phrase could still explode; and **the day clause is the one unrestricted field that speaks**, without which the commonest expression in the grammar renders `03:00 UTC` and reads as a one-off. The dom/dow union is written **`or`**, both sides in full — never *and*, which states the intersection and reads like the right answer — cron's single most misread thing, `0 0 1 * 1` firing twelve times a year **plus** fifty-two. *The rate:* the denominator is **derived rather than named** — the **400-year Gregorian cycle**, 146,097 days, 4,800 months and **exactly 20,871 weeks**, so it repeats the leap pattern and the weekday alignment *together* and every one of both appears in its true proportion. That **dissolves the ticket's question** rather than answering it: a calendar year has no defensible value (4.33 or 4.42 for `0 3 * * 1`), and *this* year is worse, the number changing on 1 January with no edit and a laptop and a runner rendering different rates for one artefact across that boundary — [#4](https://github.com/TheLoomLabs/hyper/issues/4)'s environment-as-authority-axis arriving through arithmetic. **Two significant figures** (one decimal renders the rarest expression the grammar admits, `0 0 29 2 *` at 0.0202, as `0.0` beside a Procedure that runs), **`≈` only where rounded** — which an exact denominator makes informative, `0 0 1 * *` being `1 run/month` exactly — and singular only at 1, unit fixed at runs/month. ***[#60](https://github.com/TheLoomLabs/hyper/issues/60)'s two constraints discharged:*** the rate is a **JSON number, never a band**, and **the wire carries the number the page renders**, rounded once, an unrounded value beside a rounded rendering being two representations of one derived fact that can disagree; and **nothing is ever truncated** — a truncated gloss drops, and §8's truncation marker names *an axis dropped*, meaningless inside a phrase — so `THE CODE MOVED`'s cell **stacks** expression/phrase/rate and wraps, a `FLAGS` row keeps its one-line head with both glosses beneath, and the rate gets **no row and no column** of its own, being unable to move while the Cadence stands still. *Two things found beside the answer:* §10's grammar did not say whether **a list's members may be items** — `9-11,14-16/2` legal or malformed depending on how you read five alternatives — now stated, along with *restricted* meaning **not `*`** rather than not-every-value, so `0 0 1 * 0-6` unions to every day and the phrase says so; and **ADR-0005's *roughly 8,600×* was an estimate made before there was a denominator** — it is 8,765.8, and the two rendered rates put **≈8,800×** on the screen, corrected in all four places so the number in the argument is the number on the surface the argument is about. **§12 gains no set**: its preamble already keeps the cron grammar out as the whole subject of the chapter that owns it, and the gloss is a reading of that grammar, so the preamble widens by one clause — and the words the phrase writes are exactly the ones the grammar **refuses to read on input**, which is the point rather than a tension. Glossary unchanged at **38 terms** — this ticket named a notation, not a concept.

## [A Refusal that follows a call that already reached the world](https://github.com/TheLoomLabs/hyper/issues/78)

**a guardrail that declines after a call is a halt, never a Refusal** ([ADR-0072](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0072-a-guardrail-that-declines-after-a-call-is-a-halt.md)). The ticket's asymmetry was real and its cause was sharper than the ticket knew: `record-identity-collision`'s Store site was not merely the one post-call member of a 47-member set, it was **the option [ADR-0070](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0070-an-expansions-members-are-one-record-identity-each.md) had explicitly rejected, running in the prose the whole time** — *refuse per member at its turn*, rejected one ticket earlier because *"declining there declines after an effect — and refused carries no identity set (§7), so the Step would render `–` and the write that did happen would vanish from the surface"*. Only the comparand differed, the sibling set there and the Store here, and the consequence landed identically: three serial `mutate` members, the first writing a version, the second colliding, Disposition *refused*, `RECORDS` rendering `–` beside an `expanded_to` of three over a Run that created two resources. ADR-0070 missed it because **the ticket that settled the fault had no reason to visit the site** — it needed the Expansion-internal collision to decline before any effect, established that it did, and never asked what the Store's own site does with the same fault. **Three statements of the rule and no enforcement of it**: `CONTEXT.md`'s Refusal entry, ADR-0061's *never on a Step's*, and §12's definition of exit `77` as *a guardrail declined before any effect reached the world* — the exit-code set's own text contradicted by the site, which is the third contradiction the ticket had counted as one. So the ADR is on the **invariant** rather than on the site: what was hard to reverse was not what the Store site does but that the definition is now enforced, deciding any fifth site without another ticket. **The Store comparand splits by when the identity resolves**, not by Kind: pre-call — a template hole, a `shell` `$.command`, an authored `values:` member — the Store is read at §6's Expansion beside the members' comparison against each other and a collision **Refuses** with nothing touched; response-path, the Run **halts**, Disposition *ran*, no `error_code`, `failed` at `1`, which is what `77`'s own definition had been asking for. The pre-call half **reaches two Steps the sibling test cannot**: a Step carrying no `over:`, which holds a set of one — vacuous against itself, not against the Store — and a `destroy` by literal identifier, where a `values:` member authored `Foo` against a standing `foo` survives §5's head lookup on unequal names and would otherwise open a colliding series post-call, so ADR-0070's *a `destroy` cannot reach the case* was true of the sibling comparand only. **A third comparand was found unowned**: two Records out of one `series` response that are one identity are not Expansion members — a `series` response is one call the Expansion resolved to — and a `series` Operation reads its identities from a response by construction, so it has **no pre-call form at all** and every such collision halts; whatever held the identity first keeps it, each comparand supplying the order (Expansion order, the collection's order, and nothing to decide against the Store). **Kind-blind throughout** on ADR-0070's precedent, the criterion being *the call went out* rather than *a resource exists*, which is why a polling `until:` halts on a `read` too. **Expansion gained a stated order** for what are now four checks — causal rather than arbitrary, predicates → Bound → sibling collision → Store collision, the sibling first as the only one reproducible from the artefact with no Store in hand — a gap that predated the ticket and was closed in session rather than filed. **No closed set moved**: 47 `error_code` members, four sites, seven Dispositions, seven exit codes, 37 glossary terms, and `CONTEXT.md` untouched because its definition was being *enforced* rather than amended — but §12 gained a **property of the whole set** where it had only ever had properties of members: every member declines before a call goes out. **§13 carries the Store comparand as a second limit rather than a widening**, because the two share a shape and not a price: the existing paragraph closes on *it costs one resource once*, exactly true of a collision between things one Run produced, while the Store's collides with a series that stays standing and that nothing clears or remembers — append-only Store, no Run reading an earlier Run's halt — so every Run reaches the same member, makes the same call, orphans another resource, and halts in the same place. Under a Cadence that is one orphaned resource **per occurrence, indefinitely**, at the multiplier §5 has always said a Cadence is, cleared only by a reviewed Manifest identity change and survivable only because it is loud every time.

## [How much of the Store branch does hyper fetch?](https://github.com/TheLoomLabs/hyper/issues/79)

**the Store branch is fetched shallow and whole** ([ADR-0074](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0074-the-store-branch-is-fetched-shallow-and-whole.md)). The ticket's suspicion — that depth 1 is sound and §13 is therefore overstated — was **half right, and wrong about which half**. Depth 1 is sound, and the reason was already decided everywhere except in a sentence about fetching: [ADR-0011](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0011-the-store-is-append-only.md) **explicitly rejected** deriving the Head from the branch's commit order — a genuine total order, created by the rebase-retry protocol itself, and free — *because the working tree must be self-describing*, and §7's *files are authoritative* makes every answer a directory listing or a backward scan through date partitions. Provenance carries no `store_revision`, so **every git object `hyper` reads at a revision belongs to the code branch** — the branch [#75](https://github.com/TheLoomLabs/hyper/issues/75) deepened — and the Store supplies only its tip; append-only is what makes even a year-old Run a tip read. *The answer is two halves of one thought rather than two decisions:* **the Store's history is never read and its content always is**, so the fetch is shallow and never filtered — a version's `written_at` sits inside the file, so ordering a series opens every version of it, and under a blob filter each of those is a lazy fetch that makes *a read-only Run proceeds offline* false wherever the network is, which is `hyper` manufacturing the condition [#75](https://github.com/TheLoomLabs/hyper/issues/75) made it *enforce* against. *The depth is decided by the branch's absence, not the repository's state*, and all three alternatives fail on a case: always-shallow **truncates** the ordinary laptop clone and takes `git log` from the surface specified as Compaction's own account; always-full reinstates on every scheduled Run the cost [ADR-0071](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0071-a-missing-git-object-is-an-absence-to-name-never-a-supply-to-substitute.md) rejected `fetch-depth: 0` for; and matching the repository fails *precisely where it matters*, the deepen step running **before** `hyper` and leaving the runner un-shallow. What survives is a rule about creation — **`hyper` never changes the depth of a branch it did not create** — which is [#75](https://github.com/TheLoomLabs/hyper/issues/75)'s *never deepens on its own behalf* read from the other end. *The push-back the ticket named is answered by append-only rather than by hope:* the fetch-rebase-retry reaches nothing below the boundary because the branch is only appended to and never force-pushed, so every fetch lands on a **descendant** of the boundary the last one set and the merge base is always present — a fact nobody had written down, which is what the ticket predicted would be the case if depth 1 held.

*Insufficiency:* **there is none, decidably rather than hopefully.** Every Store read — Head derivation, the backward scan for a Step's previous Run, run-once and `skip-if-recorded` evidence, a Comparison's two Journal entries, reaping, the schema-version test, `hyper show`, the Orphaned Asset report, the rebase — is the tip tree or a descendant of the boundary. So **no Store-side `not-in-clone`, no new `error_code`, no deeper fetch, and nothing for [ADR-0061](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0061-a-refusal-belongs-to-the-run-not-to-the-step.md)'s test to fire on** — a fetch that fails is already `75`. §12 did not move: the fourth attrition shape, *the set simply not being asked*.

*§13 was restated, and not in the direction the ticket guessed — it was not overstated, it named the **wrong payer**.* *every time somebody clones it* is a rare human act; the recurring payer is a scheduled Run, `actions/checkout` taking one ref so the Store is **absent on every occurrence** and fetched from scratch each time. The limit is now **two curves with two payers**: a clone pays for the whole history and Compaction reclaims nothing from it; `hyper`'s own sync pays for the **live tree**, once per environment that lacks the branch, and Compaction *does* reclaim from that one — the only place in the tool where it buys anything on the wire, which corrects the reading §7's *it reclaims nothing from a clone* invites. **And the honest limit got worse in the dimension it never mentioned:** what neither curve reclaims is the **Journal**, since Compaction removes interior Observation versions only and a version is minted only where the bytes moved — so a Record checked every five minutes and never changing costs one file while each of those Runs writes an entry that stands forever. *The term that grows with the Cadence rather than with the world is the term nothing reclaims*, and at five-minute recurrence it is the dominant term in what a runner fetches. **Two mechanical facts written down rather than relied on:** `hyper` names the Store ref explicitly, a checkout having left `remote.origin.fetch` pinned to the one ref it took — [#75](https://github.com/TheLoomLabs/hyper/issues/75)'s trap at a second site — and the Store fetch lands **after** the deepen step, re-creating `.git/shallow` with a boundary naming the Store branch alone and truncating nothing on the code branch. *Honest limit:* a `--single-branch` laptop clone gets Compaction's `git log` account one commit deep — the one clone where the two can meet, a runner never compacting and an ordinary `git clone` holding the branch whole before `hyper` touches it. *One hole filed beside the answer:* **where `hyper` materialises the Store branch locally**, unstated across fourteen sections and presumed by §7's *any index is local, ignored by git*. Glossary unchanged at **38 terms**; §12 in reach and unmoved.


## [Where does hyper materialise the Store branch locally?](https://github.com/TheLoomLabs/hyper/issues/80)

**`hyper` never checks the Store out** ([ADR-0075](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0075-hyper-never-checks-the-store-out.md)). Nowhere: the Store's files are read out of git tree objects and written with `hash-object`, `commit-tree` and `update-ref`, so no byte of Store content is ever an ordinary file on disk. §7's *files are authoritative* is unchanged — the files are the ones in the tree, and finding a Head is a listing of one. **Two of the ticket's three options were the same option**: a worktree can be placed under `.git/`, so the axis was materialised-or-not.

*The ticket's own framing had the decisive sentence backwards, and it is the first time a ticket's stated argument for an option turned out to be an argument against it.* §7 promises *the version that is current is visible to anyone reading the branch, in a fresh checkout or a browser, with no git plumbing and no tool*, which the ticket read as making the worktree **the only shape that makes it true of the checkout `hyper` itself keeps**. The browser clause gives it away: the sentence quantifies over **humans** and is a promise about what the branch *is*, not about how `hyper` reads it. And `git worktree add` **locks the branch to that worktree**, so a human on their own laptop gets `fatal: 'hyper-store' is already checked out at …` for exactly the checkout §7 offers them — the option that looked like it honoured the promise is the only one that revokes it.

*What decided it was §6's crash guarantee and not the reading path, which is where the question nobody had asked was hiding.* §6 requires a serial effectful Expansion to leave what it confirmed — *three Tombstones where the fourth call never returned, which the next Run reads* — and §7 pushes after every effectful **Step**, so those three are written between pushes and **what they are between pushes** is the whole question. In a worktree they are **uncommitted files a crashed process left**, indistinguishable from a hand-edit of evidence, which `STORE.md` names as the thing the branch exists to prevent: a materialised Store must either commit files it did not write or discard what §6 promised. So the answer is not *where* but *what* — **the Store has no uncommitted local state, ever**: one commit per confirmed write, push per effectful Step (§7 unchanged). §7's *what it wrote before it stopped stands locally* becomes literally true of the branch tip, and a torn write is unobservable, `hash-object -w` landing atomically and an unreferenced object being invisible rather than half-present. **The granularity is load-bearing rather than an economy**, and it is the one thing this shape can get wrong: a per-call write no commit reaches is unreachable and `git gc` eats it.

*Three costs the worktree carries and this does not:* a **third curve** on top of §13's two — writing the whole live tree to disk right after fetching it, on every scheduled occurrence, to read the handful of files a Run touches; an **ignore rule for a path nobody reviewed**, `.gitignore` not being among the five artefacts and the Store worktree being the only unreviewed thing `hyper` would write into the working tree, which is exactly what §7's *any index is local, ignored by git* had been presuming; and a **channel into the record the model does not otherwise have**, a `shell` Operation's `cwd` being the repository root while tree objects are unreachable by a command at all.

*Four consequences.* The local ref is **`refs/heads/hyper-store`** and not a private namespace — the record being in the open is the thesis, and a private ref would make a human's checkout fetch a branch their clone already holds; `hyper`'s own state lives under **`.git/hyper/`**. **The push retry's "rebase" becomes a path-set union and the claim gets stronger**: `git rebase` needs a worktree there is none of, `hyper` knows exactly which paths it wrote, and §7's hedge that *almost every one of those rebases is trivially clean* — an observation about how git's merge happens to behave — becomes structural, disjoint path sets being unable to collide, so **every** retry is clean but one. **The surviving conflict got its mechanism here and its evidence question filed as [#81](https://github.com/TheLoomLabs/hyper/issues/81)**: it is detected as a same-path write and the losing Run is `failed` with `75` having pushed nothing, while what the Store *holds* was equally open before this ticket — the worktree's implicit answer, conflict markers inside a file specified as canonical JSON, was never a resolution. Three facts sharpened it: it is **two** colliding paths and not one, the bytes always differ (`closed_by_run`, `ended_at`), and the irreconcilable case is not two reapers — whose content ADR-0003 fixes — but a **live-but-slow Run closing its own entry `completed` after another has reaped it `failed`**, one an observation and the other an inference. **The case-fold check stops being a rule the write could contradict**: `hyper` never puts a Record's identity on a filesystem at all, a git tree entry being a byte string and case-sensitive everywhere, so *never by attempting the write and seeing what happens* is structural rather than forbidden — **the write always succeeds** — and the check survives because a human's checkout on a case-insensitive laptop is precisely the reading §7 promises, now the only place a filesystem sees these names. Same move as [#44](https://github.com/TheLoomLabs/hyper/issues/44): unrepresentable rather than merely forbidden.

*What it costs is one runtime dependency, and it is the first time the map's single-binary premise has been charged.* **`git` is a subprocess and the one external tool the binary requires** — the surface goes from two commands to a dozen, and an embedded implementation would have to resolve git's config, credential helpers and URL rewrites to inherit the token §10's `persist-credentials: true` leaves behind, agreeing with the real thing only until it did not. §11's exemption covers what a **generated workflow** consumes on a runner; this is what the **binary** consumes on a laptop, a different claim in the same words, so §13 names it rather than letting the exemption stretch. No version pinned — every command on that path predates 2010, and a pin would be a fifth projection constant [ADR-0046](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0046-the-projections-executor-is-compiled-in-never-authored.md) closed at four.

*§12 did not move*, and [#78](https://github.com/TheLoomLabs/hyper/issues/78)'s set-wide property decided it without a ticket: a failed local object write does not decline **before a call goes out**, so it is a halt or an ordinary `failed` and mints nothing. A sixteenth attrition precedent of the *not being asked* shape, and the second where the set held because a rule about what a member **is** made the question unaskable. *One word deleted:* §7's *any index is local, ignored by git* was carrying two faults — *ignored by git* is a claim about **ignore rules** that under `.git/` there are none to make, and "index" already carried the gutter's sense across §8 and §12 with `git`'s own arriving as a third. The noun is **dropped rather than renamed**: the thing is optional, nothing refers to it, and `CONTEXT.md` has no term for it, so minting one would add a term to the ubiquitous language for something that may not exist at runtime. `Cache` was unavailable regardless — it is on the **Store's** own `_Avoid_` list. Glossary unchanged at **38 terms**.

## [What the Store holds when two Runs close one entry differently](https://github.com/TheLoomLabs/hyper/issues/81)

**Every Store path carries the id of the Run that wrote it** ([ADR-0076](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0076-every-store-path-carries-the-id-of-the-run-that-wrote-it.md)). *What the Store holds* turned out to be downstream of a grammar defect, and the answer removes the collision rather than adjudicating it. §12's grammar already held the invariant in **three of its five path forms** — a Record version is `records/…/<run-id>-<nnnn>.json`, a Journal entry `journal/…/<run-id>/…`, and no two Runs mint one UUIDv7. **The closing write was the sole breach**, naming the *dead* Run's id in files it wrote itself, which is the whole of why §7 had exactly one unclean case and why it sat there. The closer now writes **one file**, `journal/<yyyy>/<mm>/<dd>/<run-id>/closed-by/<closer-run-id>.json`, inside the dead entry and under the dead Run's date partition so *is this entry closed* stays a listing of one directory. **Two Runs cannot write one path, anywhere, in any circumstance.**

*Three facts sharpened it past the ticket's own statement.* **The population is one shape** — two runners share §10's `concurrency` group and two laptop Runs share §6's filesystem lock, so laptop-plus-runner is the entirety of it. **Overlap does not race toward the reap, it guarantees it**: there is no recency test and §6 refuses one on purpose, so the race was only ever about who pushed first. And **the collision surfaced a Step early with either side able to lose**: the reaper writes the in-flight Step file at the next `<nnnn>`, precisely the number the owner writes when that Step finishes, so the owner died at its **next Step push** — `75`, its confirmed Records for that Step going with it and every later Step never running — while the reverse order takes out the **reaper**, a Run with work of its own killed by housekeeping done for a Run that was not there.

*The sentence that could not do what it claimed.* §7's *it stands as a conflict rather than being resolved in either direction* was false of its own mechanism: first-push-wins is a resolution, in favour of whoever was earlier, in the one section whose subject is not editing evidence.

*The two-reaper case collapses.* Both write content [ADR-0003](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0003-re-running-is-the-retry.md) fixes entirely and differ only in who closed it and when — facts about the **closer**, not rival accounts of the dead Run. Several closers all stand; the close instant is the **earliest** `ended_at`, later ones adding nothing but their own existence.

*The real case is a **contested entry***, holding both an `outcome.json` its own Run wrote and a `closed-by/` file another Run wrote — what a reap of a Run that was alive after all leaves behind. **The entry's outcome is the owner's wherever one exists**: an `outcome.json` is its own Run's observation, a `closed-by/` file another Run's inference drawn from a silence, and where they disagree the observation is what happened while the inference stays true of the Run that drew it. `hyper` picks no side between two accounts of *what the world did*; this is not that, and holding both files is what keeps it from becoming that. **Contested entry** enters `CONTEXT.md` as the 39th term and **Journal**'s *open* is restated as *no account at all*.

*Two keys split on the same argument.* **`outcome` is absent** — ADR-0003 fixes it to `failed` always, so the file's existence is the whole answer — while **`disposition` stays** despite likewise holding one value: the entry's outcome is a question about the **entry**, which a file's existence answers in full, where a Disposition is a fact about a **Step** this file is the only carrier of, and §8 reads Dispositions generically across all seven. **`closed_by_run` leaves `outcome.json` entirely**, its whole job having been to mark a file as not its entry's own Run's, which the path now says — a key restating its own path being the second representation §7 refuses for durations.

*Consequences.* **Every retry is clean**, with no exception left anywhere in the Store, `75` on a push keeping the two meanings it always also had. **§6's outcome triple loses a cause** — *an entry closed by a later Run* is gone from §6 and from §12's `outcome` set, no Run's outcome being reachable from another Run's entry. **The push re-applies the whole unpushed set**, every local commit the remote does not hold rather than this Run's alone, which is what makes §7's *what it wrote before it stopped … goes out with the next Run that syncs* true rather than aspirational; the ticket's poisoned-machine hazard was a **symptom of the broken invariant**, since a stranded path carries its writer's id and nothing can ever have taken it. **The reap folds into the sync**, decided from the same fetched tip and pushed with `run.json` so the reach count is unchanged, covering **every** open entry found — a subset needs a criterion and the only candidates are age and liveness, both the guess §6 declines — and a Run declining at a later gate has already reaped, for the same reason its entry is pushed before the gates at all. **A contested entry renders the owner's outcome and duration unqualified**, all three reaped-entry special cases turning off including the Comparison window end, with the contest as a stated line beneath §8's header and a marker on the `runs` row; **`hyper run` says nothing**, the owner noticing only if its final push happened to be rejected and re-applied, which would make the tool's word depend on push ordering.

*Two closed sets moved and three did not.* The Store path grammar goes **5→6** and the schema integers **4→5**. `error_code` held on [#78](https://github.com/TheLoomLabs/hyper/issues/78)'s set-wide property for the third ticket running — nothing here declines before a call goes out — and Disposition held, the reaper still writing *attempted, outcome unknown* at a different path. **`FLAGS` was not asked at all**, indexing the review gutter over artefact lines where a Journal entry never reaches, which is a seventeenth attrition precedent of the *not being asked* shape.

*The limit it exposed rather than accepted.* **Two effectful Runs across the laptop and a runner are serialised by nothing** — §6's lock is one filesystem's, §10's group covers runner-to-runner, and the pair falls between them. §13 carries it as a sibling of the two-clocks limit already there: same shape, two machines with no shared authority, same remedy ruled out by [ADR-0006](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0006-the-record-travels-in-the-repository.md). What is exposed is the **world** and never the evidence, the record surviving the overlap intact — which is why this is not an entry in the shape of [#78](https://github.com/TheLoomLabs/hyper/issues/78)'s. Nothing detects the overlap and nothing could without the lock, so the reap had to be made **harmless rather than accurate**. [ADR-0075](https://github.com/TheLoomLabs/hyper/blob/main/docs/adr/0075-hyper-never-checks-the-store-out.md)'s surviving-conflict consequence is marked superseded; nothing else in it moves, and it is what made the question askable.
